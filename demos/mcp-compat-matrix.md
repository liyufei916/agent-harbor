# MCP 兼容矩阵（产品边界）

Harbor **不承诺**「市面每一个 MCP 开箱即用」。下表写清当前实现能到哪；连接失败时优先对照本表，勿默认是 Key 问题。

## 协议版本 × 认证 × 传输

| 协议版本（initialize） | Token（Bearer） | OAuth（本机回环） | 宿主 stdio |
|---|---|---|---|
| **2025-03-26**（客户端优先提出） | ✅ 主路径 | ✅ 高级轨（自备 Client） | ✅ 经回环桥 |
| **2025-06-18** | ✅ 若上游在 initialize 结果中返回且被接受 | ✅ 同上 | ✅ 同上 |
| **2024-11-05** | ✅ 同上 | ✅ 同上 | ✅ 同上 |
| 其它 / 空 / 不匹配 | ❌ 连接探测失败（`UPSTREAM_DOWN` 类） | ❌ | ❌ |

说明：探测时客户端发送优先版本；**上游返回的 `protocolVersion` 须落在接受列表**。未在表中的版本需改代码扩表后再测。

## 工具集

| 环节 | 行为 |
|---|---|
| 连接探测 | `tools/list` 分页发现；自定义 MCP 把发现结果写入账号 `tools[]` |
| 固定 profile | 策略里声明的工具名须在发现集合中（否则探测失败） |
| **会话内调用** | Gate `tools/call` **按挂载白名单动态校验**（非仅连接时一次快照）；未在白名单 → 拒绝，不代填凭据 |
| 无 tools 能力 | initialize 无 `capabilities.tools` → 探测失败 |

## 传输与信任

| 方式 | 进程位置 | 密钥 | 产品文案 |
|---|---|---|---|
| 远程 HTTP（streamable） | 上游 | 宿主机 Gate 注入 | 默认推荐 |
| OAuth | 同上 | 本机换票后存引用 | 高级；需 Client ID/Secret |
| stdio | **宿主**（非沙箱内） | 不进沙箱；经回环桥 | 「更高信任」；不承诺任意 npm 包零配置 |

## 与「所有主流 MCP」的落差

- 协议写死/窄接受列表 → 老版本或私有方言 MCP 会连不上  
- 工具必须可 list，且调用须过白名单  
- stdio 依赖本机命令与 PATH，隔离模型与远程 HTTP 不同
