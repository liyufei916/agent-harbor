# 人工录屏演示脚本

本脚本按当前工作树的页面与 Go 实现整理，适用于真实桌面应用。目标是展示“Agent 能完成任务，用户能看见并控制边界”。建议主片 10–12 分钟，扩展片 3–5 分钟。录制前必须使用自己的真实模型与 MCP 组合预演；本文不代表真实远程验收已通过。

## 一、演示主线与亮点

主线：宿主机配置模型与工具 → 安全副本启动真实 Agent → 读写文件 → 同会话追问 → 认证 MCP 查询 → 核对原目录未改变 → 主动导回 → 停止、清理、再次运行。

| 核心亮点 | 镜头中的证据 |
|---|---|
| 桌面统一管理 Agent | 真实绑定、隔离就绪、Agent 版本与可用状态 |
| 模型与工具凭据留在宿主机 | 密码框、提交后清空、列表不回显完整 Key；实际架构依据为 Secrets/Gate/Kit，不把密码框当作安全证明 |
| 默认保护原项目 | clone 标识、原目录/副本路径、导回前后宿主文件对比 |
| 真实编码与多轮上下文 | 文件任务、第二轮不重复代号的追问、结果文件 |
| 认证 MCP 经 Gate 使用 | 已连接工具、工具结果与对应审计，不只展示 Agent 自述 |
| 权限可理解 | 权限一览中工作区、网络主机、MCP 范围 |
| 生命周期可控 | 停止后终态、保留或销毁副本、再次开始 |

## 二、录制前准备（不计入正片）

1. 使用 Runtime 支持的非 root macOS 环境。当前支持门槛以真实隔离检测为准；代码针对 Darwin 25 / arm64。隔离检测失败时先排障，不降低限制。
2. 构建包含最新修复的应用。当前工作树含 dsh 插件路径修复，若使用 dsh，必须重新构建 Go 后端并新建会话。
3. 主线选 Claude Code 或 dsh 中已经预演成功的一种，不在录制时首次验证供应商。另一种放加长版。
4. 确认 Agent 检测可用、模型余额充足、认证 MCP 工具能执行只读请求。
5. 选择一个稳定 MCP。可用 Context7，但先在应用中连接成功，记下实际返回的工具名称、输入要求与预期结果；不要假定工具名永远不变。
6. 模型/MCP Key 在应用中录入。录制不展示终端环境、剪贴板、完整 Key、登录浏览器隐私或真实业务项目。
7. 通知勿扰，固定窗口尺寸，使用清晰字号；录应用窗口，并为宿主文件核对预留一个干净的 Finder/文本窗口。
8. 设置“结束与清理”：停止时询问是否清除，或默认保留。主线需要先保留副本，避免演示结果被销毁。

### 2.1 专用工作区

以下命令在宿主终端执行一次，创建唯一的新目录，不覆盖已有演示结果。记录输出的路径，后续在应用中选它。

```bash
python3 - <<'PY'
from pathlib import Path
from tempfile import mkdtemp
root = Path(mkdtemp(prefix='harbor-recording-', dir=Path.home()))
for name in ('project-a', 'project-b'):
    p = root / name
    p.mkdir()
    (p / 'input.txt').write_text('Agent Harbor 演示项目\n目标：安全运行编码代理\n', encoding='utf-8')
    (p / 'result.md').write_text('ORIGINAL — 尚未导回\n', encoding='utf-8')
(root / 'outside-canary.txt').write_text('NON_SECRET_OUTSIDE_WORKSPACE\n', encoding='utf-8')
print(root)
print('主线工作区：', root / 'project-a')
print('双会话工作区：', root / 'project-b')
print('可选隔离探针：', root / 'outside-canary.txt')
PY
```

不要选择整个新建根目录；只授权 `project-a`，这样外部 canary 位于授权目录之外。两个工作区均不放符号链接、密钥或真实项目。

### 2.2 启动与账号配置

仓库根目录启动真实桌面：

```bash
./scripts/dev-desktop.sh
```

| Agent | 模型页选择 | 前置条件 |
|---|---|---|
| Claude Code | 自定义模型（Claude） | 页面填 Anthropic Messages 兼容地址、模型名、Key；此方式不需要 Claude 模型环境变量 |
| dsh | DeepSeek dsh，`dsh-model` | 独立安装固定版 dsh/Node；宿主登记 `HARBOR_DSH_*` 上游与路径；Key 在页面输入 |
| Codex | OpenAI Codex，`codex-model` | 安装 CLI，宿主登记 `HARBOR_CODEX_*` Responses 上游；Key 在页面输入 |

预置 profile 与 custom 不能随意混用。dsh 的 DeepSeek 配置示例为 origin `https://api.deepseek.com`、BasePath `/anthropic`、模型 `deepseek-chat`，实际以账号可用模型为准。环境变量示例见 [dsh 文档](../docs/DSH-INTEGRATION.md)、[Codex 文档](../docs/CODEX-INTEGRATION.md)。

工具页使用“API Key / Token”：名称、服务地址、Token；填写地址时 profile 一般保留 `custom`。连接后确认列表有真实工具数量。主线无需额外登记 MCP 环境变量。不要以“跳过上游探测并保存”代替真实连接成功。

完整预演一次，确认文件任务、第二轮、工具查询、停止与导回都成功后，再用新的演示工作区录制。

## 三、主片逐镜步骤（10–12 分钟）

时间仅作节奏参考；模型等待可剪短并标注“等待已剪辑”，保留关键请求、结果和状态切换。

### 镜头 1：产品定位与真实环境（0:00–0:40）

1. 打开 HOME，停留在顶栏“真实绑定”和侧栏“隔离就绪”。
2. 展示 HOME、模型、工具、设置四个入口。
3. 不展开技术文档，不展示开发终端堆栈。

旁白：“Agent Harbor 是桌面级 Agent 安全沙箱。我们在授权工作区内运行真实编码代理，模型与工具凭据由宿主机安全闸口管理。”

通过画面：真实绑定、隔离检测通过。浏览器的“模拟模式”不能混入本片作为真实能力证据。

### 镜头 2：一次配置，按会话使用（0:40–1:40）

1. 进入“模型”，展示已连接的演示账号。
2. 如需展示添加流程：填名称、正确 Agent profile、自定义地址/模型等所需字段；暂停录制后输入真实 Key，恢复录制并保存。
3. 展示保存后的账号列表；如打开编辑，只停留在不回显完整 Key 的状态，然后取消。
4. 进入“工具”，展示已连接 MCP 的主机与工具数量。

旁白：“账号在本机配置。每次会话只选择需要的模型和工具，Agent 不直接拿到上游真实密钥。”

注意：页面隐藏 Key 只是交互表现；密钥外置还依赖后端 Gate 代填与私有配置。录屏不要打开会话配置或环境来寻找 Key/Sentinel。

### 镜头 3：四步启动与安全副本（1:40–2:40）

1. HOME →“新会话”。
2. 工作区选新建的 `project-a`。
3. 挂载选择“安全副本（推荐）”，停留 2 秒。
4. 选择已检测可用的 Claude Code 或 dsh，展示版本。
5. 选择对应模型账号。
6. 勾选已连接的 MCP，填入下面第一轮任务，点击开始。
7. 保留 `provisioning → running` 的状态画面。

第一轮任务：

```text
读取当前工作区的 input.txt。
把 result.md 改成一份简短 Markdown 报告，包含：
1. 标题“Agent Harbor 演示结果”；
2. 项目目标的两句总结；
3. 一行“版本：1”。
本次对话的项目代号是 HARBOR-DEMO-42，请记住，但不要把代号写入文件。
只操作当前工作区的 input.txt 和 result.md；不要使用 shell、安装依赖或访问其它目录。
完成后概述实际修改。
```

旁白：“默认在安全副本内工作。Agent 可以执行文件任务，原始目录是否接收结果由用户决定。”

### 镜头 4：真实任务结果与边界（2:40–4:00）

1. 等第一轮回答结束，展示可读流式输出。
2. 指向工作台的 Agent、原目录/副本路径、安全副本标记、工具数量。
3. 打开“权限一览”，展示文件范围、默认不可见路径类别、网络白名单和 MCP。
4. 关闭权限抽屉，展示活动/审计摘要中的实际记录。
5. 在宿主文件窗口打开 `project-a/result.md`，此时必须仍为 `ORIGINAL — 尚未导回`。

旁白：“任务已经在副本完成，但宿主原文件仍保持原样。工作台同时展示当前工作区、可用工具和网络边界。”

结果判断：Agent 自称完成不足以证明写盘；接下来的文件回读与最终导回文件应一致。权限一览是范围展示，不替代 OS 隔离负例测试。

### 镜头 5：同一会话多轮追问（4:00–5:10）

1. 在工作台**下方输入框**输入第二轮；不要在终端显示区域直接敲字。
2. Enter 发送，Shift+Enter 换行；也可点“发送”。
3. 保留同一个 session ID 和工作区画面。

第二轮任务：

```text
先回答我上一轮要求你记住的项目代号，不要猜测。
然后在现有 result.md 保留前文，把“版本：1”改成“版本：2”，追加一段“多轮对话验证”。
最后回读 result.md，展示最终内容。仍然只修改这个文件，不使用 shell。
```

通过画面：回答 `HARBOR-DEMO-42`，文件内容有“版本：2”和新增段落，session ID 不变。

旁白：“在同一个会话继续任务，保留上下文与文件修改过程。”

此镜头用于 Claude/dsh；当前 Codex 使用一次性 `exec --json --ephemeral` 路径，不把同会话多轮作为 Codex 已支持能力展示。

### 镜头 6：真实认证 MCP 查询（5:10–6:40）

1. 发送下面第三轮任务；录前把占位符全部换成实际连接的工具与参数。
2. 如工具需要先查 ID 再查资料，按真实 schema 明确两步，不要求模型猜测 API。
3. 展示真实工具结果、来源与 MCP 审计记录，再展示结果文件的新增段落。

```text
使用本会话已挂载的 MCP 工具完成一次只读查询：
工具名称：<实际工具名>
查询内容及参数：<按真实工具 schema 准备的非敏感查询>
把查询结论用三条要点追加到 result.md 的“外部资料”小节。
最后说明实际调用了哪个工具，并保留工具提供的来源信息。
如果调用失败，请如实报告，不要编造查询结果；不要访问未授权网站。
```

Context7 可用主题：“查询 Wails v3 的 Go 方法绑定与事件通信，给出三个要点”。实际工具名、库 ID 及是否可检索到相应资料，均须预演确认。

旁白：“Agent 通过 Harbor Gateway 调用本次授权的 MCP。工具认证留在宿主机，结果进入当前任务。”

通过画面：实际工具调用与结果相符，审计可对应目标或工具；模型回答有资料不等于 MCP 真正被调用。

### 镜头 7：先核对，再导回（6:40–8:10）

1. Agent 空闲后再次展示宿主 `project-a/result.md`，确认仍为原始标记。
2. 返回工作台，点“停止”；根据当前设置选择**仅停止/保留**，不要清除副本。
3. 等待真实终态与清理结果，不把 `stopping` 当作完成。
4. 点“导回原文件夹”，展示覆盖写回的确认，再确认导回。
5. 宿主重新打开 `result.md`，展示“版本：2”“多轮对话验证”“外部资料”等内容。

旁白：“先停止 Agent，再由用户确认接收结果。导回前原文件不变，导回后才看到本次成果。”

当前导回是合并复制并覆盖同名文件，不删除原目录多余文件；不要描述为 Git 合并、冲突解决、原子提交或完整回滚。

### 镜头 8：清理与再次开始（8:10–9:20）

1. 回 HOME，展示已停止会话。
2. 点“再次开始”，确认新会话沿用配置并能启动；可用简短任务完成一次验证。
3. 停止新会话，选择适当的清理动作。
4. 对旧的已导回会话点“销毁”，保留二次确认镜头。
5. 展示本机模型与工具账号仍在；不要承诺销毁会清除已导回文件或宿主凭据。

旁白：“停止结束 Agent 执行，销毁清除保留的隔离运行数据。宿主模型与工具账号独立管理，可以继续用于新会话。”

如果要宣称“无残留进程”，应另附对应会话 PID/进程树的实际核对；仅凭按钮状态不要作该结论。

### 镜头 9：收尾（9:20–10:00）

停留在 HOME 或最终结果文件，旁白：

“刚才我们完成了真实编码、多轮追问和认证工具查询。整个过程使用独立工作区副本，权限边界可见，成果由用户确认导回，执行过程可以停止和清理。”

## 四、加长版镜头（按预演结果选择）

### 4.1 双会话与工作区互斥（约 2 分钟）

1. 用 Claude/dsh 在 `project-a` 启动一个保持交互的会话，回 HOME。
2. 只有一个活动会话时，再尝试同一原始工作区，展示 `WORKSPACE_BUSY`；不因 clone 而允许同原目录双开。
3. 换成 `project-b` 启动第二个会话，HOME 展示运行中 `2/2`。
4. 切换两个工作台，用不同提示文案展示独立上下文和路径。
5. 达到上限时展示新会话入口限制；若当前入口可提交，预期返回 `SESSION_LIMIT`，不要为了录到错误强行绕开界面。
6. 停止一条，展示容量释放。

旁白：“最多同时运行两条，同一工作区互斥，每条会话有独立的工作区和权限配置。”

### 4.2 兼容模型账号切换（约 1 分钟）

提前准备两个已连接、相同 profile 和相同主机的兼容账号，并完成预演。在正在运行的工作台通过模型下拉框切到另一个账号，再发一轮短任务。

旁白：“兼容账号切换不重建工作区，后续请求使用新账号。”

这是模型账号绑定切换；当前不支持任意供应商、跨协议或任意模型名热切换。在途请求继续用原账号。不要仅凭下拉框变化声称已经换了模型权重。

### 4.3 多 Agent（约 1 分钟）

设置 → Agent 检测，展示实际安装可用的 Claude/dsh/Codex。停止现有会话后，新建会话选择另一 Agent 和其对应模型账号，执行一条读文件/写文件任务。

不要直接在运行会话中切 Agent。Codex 演示一次性任务；dsh/Claude 可展示多轮。未通过检测的 Agent 保留不可用原因，不能口述成已验收。

### 4.4 安全负例（技术评审附片）

仅用准备好的非敏感 `outside-canary.txt`：在授权 `project-a` 的会话中，请 Agent 使用文件读取工具读取工作区外 canary，且不要使用 shell。预期不能取得文件内容。

必须出现真实工具访问拒绝证据，才能作为这一次边界测试；模型自行拒绝或未发起读取，只能说明模型没有执行，不能证明 OS 隔离有效。不要用真实 SSH 私钥、钥匙串或 `.env` 做录屏探针。

未授权网络请求不一定弹扩权框：OS 直接出站拒绝与 Gate 可处理的扩权路径不同。不要通过执行任意 `curl` 或假定 Agent 具有浏览工具来安排现场镜头。

### 4.5 扩权与 OAuth（可选交互附片）

- 工作台“演示扩权（仅界面）”是 UI 演练；如录制，必须打字幕“界面演练，不代表真实网络授权”。
- 真实扩权需预先验证可触发的 Gate 场景，再展示拒绝、仅本次、本项目等行为，以及相应实际请求和审计。不要将一次审批扩大描述为任意网络已放行。
- OAuth 只有在真实服务登录、回调换票、工具调用均预演通过后才录。没有合适服务就展示 Token 主线；不混入 mock 自动成功画面。

## 五、录前与录后核对

- 顶栏真实绑定、隔离检测通过、当前 Agent 与模型 profile 匹配。
- 原目录初始标记明确，clone 内结果确实由本次任务产生。
- 第二轮 session ID 不变，代号回答正确且未在第二轮重新提示。
- MCP 调用有真实结果和对应记录；失败如实展示或排障后重录。
- 导回前后文件变化可核对；销毁前已保存所需成果。
- 无完整凭据、Sentinel、个人隐私或真实业务数据入镜。
- 演示结束后停止全部活动会话；一次录屏不自动代表完整安全验收通过。

实现核对入口：`internal/desktop/wire.go`（三 Agent 注册、dsh 多轮）、`internal/kits/`（各 Agent 启动能力）、`internal/orchestrator/`（状态、多会话、账号切换）、`internal/runtime/`（隔离、副本、导回）、`internal/gate/`（模型/MCP 出站）、`frontend/src/views/`（真实页面操作）。

历史文档存在滞后：研发 A 交付表仍写 Codex 未注册；旧 dsh 文档仍写无交互、停止即删除等历史行为；旧 demos 文档写自定义地址不能在前端配置。这些描述不能直接用于当前录屏。当前脚本以实际实现为依据，完整人工验收仍参照 [人工联调手册](../docs/MANUAL-INTEGRATION-TEST.md) 并核对当前版本。
