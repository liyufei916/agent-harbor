## 1. 设计目标

1. **安全可感知但不吓人**：用户始终能看见「现在边界是什么」，但不堆术语。
2. **主路径短**：选文件夹 → 选 Agent → 选模型 → 开始（工具可跳过）。
3. **厂商密钥永不出现在沙箱相关文案/表单**：录入只发生在本机的「模型 / 工具」页。
4. **扩权打断要可读**：一句话说明谁要访问什么，三个按钮结束决策。

非目标：**不做 IDE**（无目录树 / 文件编辑器三分栏；与 `DESIGN.md` §3.2 一致）；不做复杂策略编辑器；高级技术详情默认折叠。

## 2. 信息架构

```
Agent Harbor
├── HOME                   会话列表 + 一键「新会话」
├── 新会话（Wizard）       四步：工作区 → Agent → 模型 → 工具（可跳过）
├── 工作台（Session）      运行中：边界条 + 当前模型 + 终端；可多会话切换焦点
├── 模型               让 Agent「能对话」：Claude/OpenAI 等登录（原「密钥」）
├── 工具               让 Agent「能办事」：Notion 等 MCP（原「工具」）
├── 设置                   Agent 检测、会话默认、扩权、清理、关于
├── 首次引导（Onboarding） 一屏三句 + 检测隔离
└── 系统级打断
    ├── 扩权请求（Modal / 通知）
    └── 隔离不可用（阻断页）
```

导航：左侧主入口 **HOME / 模型 / 工具 / 记录 / 设置**。「工作台」仅在有 `running` 会话时出现在内容区，不强占侧栏。

**二者怎么区分（对人一句话）**

| 页面 | 一句话 | 解决的问题 | 本机代填组件 |
|---|---|---|---|
| **模型** | 给 Agent 一把「嘴」——能调大模型 | 没配 Key 就没法聊天/写代码 | Credential **Proxy** |
| **工具** | 给 Agent 一双手——能查 Notion、GitHub… | 只会聊天、办不了外部事 | MCP **Gateway** |

相同点：都在本机存凭证、沙箱里都只有 Sentinel。
不同点：**连的不是一类服务**；**录入方式也不同（已拍板）**：

| | 模型（V1） | 工具（V1） |
|---|---|---|
| 配置形态 | **仅** OpenAPI：名称 + 请求地址 + API Key；**可自由添加**，不强制预置下拉 | **双轨**：浏览器 OAuth/SSO **或** API Key/Token |
| 浏览器登录 | **不做** | 保留 |
| 列表 | **只展示已添加的项**（没有「未配置」占位行） | 只展示已添加的 MCP |
| 状态文案 | 无状态或仅 ▲ 无效（401）；默认即「已在列表 = 可用」 | ● 已连接 / ▲ 无效（去编辑） |

侧栏副标题：模型「地址 + Key」；工具「MCP 扩展」。

## 3. 视觉与文案原则

| 原则 | 做法 |
|---|---|
| 品牌 | 窗口标题与侧栏顶部固定 **Agent Harbor**；副文案「密钥留在本机 · Agent 隔离运行」 |
| 状态色 | 安全正常=沉稳绿点；等待授权=琥珀；失败/高风险=红；处理中=中性灰动画 |
| 用语 | 「隔离运行」「密钥留在本机」「经安全闸口」；避免 microVM / proxy / seccomp |
| 密钥 | UI 只显示「已连接 / ▲ 无效」；粘贴框提交后立即清空；改凭证走「编辑」 |
| 密度 | 主路径大按钮、少卡片；列表页才用轻分隔，不做仪表盘堆指标 |

## 4. 全局框架

```
┌─────────────────────────────────────────────────────────┐
│ Agent Harbor  [徽章]     [当前会话 ▾]  [使用教程]        │
├────────┬────────────────────────────────────────────────┤
│ HOME   │  内容区（随路由切换）                            │
│ 模型   │                                                │
│ 工具   │                                                │
│ 设置   │                                                │
│ [ « ]  │                                                │
│ ────── │                                                │
│ 状态灯 │  「隔离就绪」或「隔离不可用」                     │
└────────┴────────────────────────────────────────────────┘
```

| 顶栏 | 说明 |
|---|---|
| 徽章 | mock：「模拟模式」+ 横幅；http-live：「本机 live（浏览器）」（无横幅）；桌面：无模式徽章；隔离用 Seatbelt/Docker 标记 |
| 使用教程 | 右上角打开上手步骤；弹窗内可打开完整「使用说明」 |

侧栏**收缩**后：

```
┌──┬──────────────────────────────────────────────────────┐
│⌂ │  内容区加宽（尤其工作台对话区）                         │
│… │                                                      │
│» │                                                      │
└──┴──────────────────────────────────────────────────────┘
```

| 规则 | 说明 |
|---|---|
| 展开宽 | 约 200px；显示文案导航 |
| 收缩宽 | 约 52px；仅图标 + 展开按钮；**鼠标悬浮**在条目右侧浮出完整名称（如「工作台」），展开按钮浮出「展开侧栏」 |
| 切换入口 | 侧栏底部「« / »」；快捷键可选 `⌘B` / `Ctrl+B`（与常见编辑器习惯接近，但不表示本产品是 IDE） |
| 默认 | 展开；进入**工作台**时**可自动收缩**（设置开关，默认开）；离开工作台恢复「侧栏默认」；本次停留内手动展开则不再自动收 |
| 记忆 | 用户手动展开/收缩写入本机偏好（「侧栏默认」），下次启动沿用；工作台自动收缩为临时态，不覆盖默认 |
| 目的 | 给工作台对话区 / 摘要更多横向空间，便于盯输出与扩权，而非做成编辑器布局 |

- 窗宽建议最小 1100×720（侧栏收缩后内容区更宽）。
- 底侧「状态灯」绑定 Runtime 健康检查；红灯时「新会话」禁用并链到阻断说明；收缩态仍显示小灯。

## 5. 页面逐屏

### 5.1 首次引导 Onboarding

**目的**：建立心智，检测能力。

```
┌──────────────────────────────────────┐
│         Agent Harbor                 │
│                                      │
│  1. Agent 在隔离环境中运行            │
│  2. API Key / 密码只存在你这台电脑上  │
│  3. 工具在本机配置一次，沙箱里不用填密 │
│                                      │
│  隔离能力检测（逐条至完成）           │
│  · Seatbelt：系统环境 / 探测区 / …   │
│  · Docker：CLI / daemon / 网络 / …   │
│  ● 隔离能力可用 → [ 进入 HOME ]      │
│  ○ 失败 → [ 改隔离 / 引擎设置 ]      │
└──────────────────────────────────────┘
```

| 元素 | 规则 |
|---|---|
| 检测过程 | 与设置「重新检测隔离」、阻断页「重新检测」**同一套七项**；文案随当前隔离后端（Seatbelt / Docker）切换；一次 `GetRuntimeHealth`，界面分阶段上屏 |
| 检测失败 | 主按钮不可用；可「重新检测」与「改隔离 / 引擎设置」；禁止「仍要继续」/跳过 |
| 再次引导 | 设置「下次启动重新显示引导」清标记后，冷启动再跑本屏（含逐条检测） |
| 跳过 | 不提供跳过检测 |

---

### 5.2 HOME

**目的**：会话中心；最常见落地页。支持多条会话记录；**并行 running 有上限**。

#### 5.2.1 并行规则（V1 已拍板 · 方案 C）

| 规则 | V1 |
|---|---|
| 会话记录条数 | 不限（含已停止） |
| 同时 `running`（含扩权等待中，无独立 `awaiting_permission` 态） | **最多 5 条** |
| 相同 Agent 壳 + **不同工作区** | **允许**同时 running |
| 相同工作区（路径规范化后相同）+ 任一 Agent | **禁止**第二个 running |
| 达上限再开新会话 | 「新会话」可进向导，点「开始运行」时拦截：「已有 5 个会话在运行，请先停止其中一个」 |
| 同工作区冲突 | Step1 选中或开始时提示：「该文件夹已有运行中的会话」，禁止开始；可提供「打开已有会话」 |

工作区路径比较：解析为绝对路径后再比（`~`、符号链接按解析后路径）。

#### 5.2.2 列表

```
┌─ HOME ──────────────────────────────────────────────┐
│  我的会话 · 运行中 2/5                 [ + 新会话 ]  │
│                                                      │
│  ┌────────────────────────────────────────────────┐ │
│  │ Claude Code · DeepSeek · ~/work/foo  ● 运行中   │ │
│  │ 工具: Notion · 挂载: 安全副本                   │ │
│  │                    [ 打开工作台 ] [ 停止 ]      │ │
│  └────────────────────────────────────────────────┘ │
│  ┌────────────────────────────────────────────────┐ │
│  │ Claude Code · Anthropic · ~/work/bar ● 运行中   │ │
│  │ 工具: 无 · 挂载: 直接编辑                       │ │
│  │                    [ 打开工作台 ] [ 停止 ]      │ │
│  └────────────────────────────────────────────────┘ │
│  ┌────────────────────────────────────────────────┐ │
│  │ Codex · OpenAI · ~/work/old         ○ 已停止    │ │
│  │                    [ 再次开始 ] [ 销毁 ]        │ │
│  └────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────┘
```

| 字段 | 来源 |
|---|---|
| Agent 名 | session.agent |
| 当前模型 | session.model_account（显示名） |
| 路径 | session.workspace（`~` 缩写） |
| 状态点 | state 映射 |
| 工具摘要 | 已挂载 MCP，最多 3 个 |
| 挂载 | `clone` / `direct` |
| 运行中计数 | 顶栏 `运行中 x/5` |

操作：

- **打开工作台**：切换焦点到该会话（不另起进程）
- **停止** / **销毁**：同前；销毁二次确认
- **再次开始**：对这条已停止会话调用 `StartSession`，同一 `session_id` 回到 provisioning / running 并进入工作台。不另建会话，不留下一条 stopped 副本。清理未完成时不能开启。进程在停止时已退出，重新开启后停在下一轮输入，不再自动送入创建时的任务。返回 HOME 再打开同一会话时，工作台保留已展示的输入和输出。

### 5.3 新会话 Wizard（核心友好路径）

四步，顶部步进条：**工作区 → Agent → 模型 → 工具**。工具可「跳过」。

#### Step 1 工作区

```
│  选择要隔离运行的项目文件夹                            │
│  ┌ 本机 Agent CLI（先检） ──────────── [重新检测] ┐ │
│  │ Claude ● / Codex ○ / dsh ○                     │ │
│  └────────────────────────────────────────────────┘ │
│  ┌────────────────────────────────────────────────┐ │
│  │  拖拽文件夹到此处，或 [ 选择文件夹 ]              │ │
│  └────────────────────────────────────────────────┘ │
│  已选：~/Projects/demo                               │
│                                                      │
│  文件怎么进隔离环境？                                 │
│  ( ) 安全副本（推荐）  在副本里改，工作台「导回原文件夹」一键写回 │
│  (•) 直接编辑          改动立刻写回该文件夹           │
│                                                      │
│                              [ 下一步 ]              │
```

- **无可用 Agent CLI 时「下一步」禁用**（须本机 Detect 至少一台）。
- 未选文件夹时「下一步」禁用。
- 选中后轻量提示：「SSH 密钥等敏感目录不会进入隔离环境」。
- 若该路径已有 **running** 会话：横幅提示并禁用「下一步」，提供「打开已有会话」。

#### Step 2 Agent（壳）

```
│  选择要运行的 Agent                    [ 重新检测 ]   │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐       │
│  │ Claude Code│ │   Codex    │ │    dsh     │       │
│  │  ● 可用    │ │  ● 可用    │ │  ○ 未安装  │       │
│  │            │ │            │ │ [安装说明] │       │
│  └────────────┘ └────────────┘ └────────────┘       │
│                                                      │
│                    [ 上一步 ]  [ 下一步 ]             │
```

**检测与展示（已拍板）**：预置始终展示；进入本步自动检测；可手动重新检测；未安装灰显；无自定义 Agent 表单。
未选中可用 Agent：「下一步」禁用。

#### Step 3 模型（脑）

```
│  本会话使用的模型                                      │
│  同一时间只用一个；进入工作台后仍可切换。               │
│                                                      │
│  模型  [ 我的 DeepSeek ▾ ]                             │
│         · 我的 DeepSeek                                │
│         · 公司网关                                     │
│                                                      │
│  还没有模型？ [ 去添加 ]                               │
│                                                      │
│                    [ 上一步 ]  [ 下一步 ]             │
```

- **用下拉框**，选项 = 「模型」里**已添加**的项（显示名称）；与工作台「当前模型」同一数据源。
- 不在此步新建账号、不展示厂商预置清单；要加新的去「模型」页。
- 空列表：下拉禁用 +「下一步」禁用，引导「去添加」。
- ▲ 无效项：可灰显不可选，或可选但点「下一步」时提示先编辑。
- 写入 `createSession({ modelAccountId })`。

#### Step 4 工具（可跳过）

```
│  需要哪些工具？（可跳过）                          │
│  与模型无关；这里是 MCP。                          │
│                                                      │
│  ☑ GitHub MCP  ● 已连接                               │
│  ☑ Notion      ● 已连接                               │
│  ☐ Slack       ○ 未添加   [ 去添加 ]                  │
│                                                      │
│         [ 上一步 ]  [ 跳过 ]  [ 开始运行 ]            │
```

- 「开始运行」前校验：运行中少于 2；工作区无冲突；模型已连接。
- 通过则 `createSession`；进入工作台并 provisioning。
- 失败：停留本步或回 HOME，展示原因。

### 5.4 工作台 Session（运行中主界面）

一次界面只聚焦 **一个** 会话；多 running 时用顶栏会话切换或回 HOME「打开工作台」。

**不是 IDE**：无左侧项目目录、无中间代码编辑区。布局固定为「边界条 + PTY + 摘要/活动」。需要改源码时「在系统编辑器 / Finder 打开工作区」（可选入口，V1 可只做文案提示）。侧栏可收缩以加大 PTY 区（见 §4）。

```
┌─ 边界条 ─────────────────────────────────────────────┐
│ ● 隔离运行中  Claude Code · ~/work/foo                │
│ 当前模型 [ 我的 DeepSeek ▾ ]   文件:安全副本  工具:2 │
│     [ 权限一览 ] [ 导回原文件夹 ] [ 停止 ]             │
├──────────────────────────────────┬───────────────────┤
│                                  │  本趟摘要          │
│         终端 / Agent 输出         │  · 请求 128        │
│         （PTY）                   │  · 拒绝 2          │
│                                  │  · 工具调用 15     │
│                                  │  最近活动 …        │
└──────────────────────────────────┴───────────────────┘
```

| 区域 | 规则 |
|---|---|
| 边界条 | 常驻；含 Agent、工作区、**当前模型** |
| 当前模型 | 下拉 = 已连接的模型；切换只影响**之后**出站；壳与工作区不变；调 `switchModel(sessionId, modelAccountId)` |
| 切换会话 | 列出其他 running；切焦点与 PTY，不停止原会话 |
| 导回原文件夹 | 仅 `mountMode=clone`；`SyncBackWorkspace` 合并写回 `sourceWorkspace`；销毁前仍可导回 |
| 终端 | 内嵌 PTY，绑定当前焦点 session |
| awaiting | 边界条变琥珀 + 扩权模态（须标明会话） |
| 侧栏 | 进入本页宜收缩，便于操作终端与看右侧摘要 |

### 5.5 权限一览（弹窗）

工作台顶栏「权限一览」打开**模态弹窗**（与扩权 Modal 同层 `modal-root`）；以只读展示边界为主；**网络「记住的允许」可在此撤销**（工作台内改错「本项目始终允许」的主入口，不必先去设置）。Esc /「关闭」退出。

```
┌─ 当前边界 ──────────────────────────── [ 关闭 ] ─┐
│  文件                                              │
│   · 可读写：~/work/foo（安全副本）                  │
│   · 默认不可见：SSH 密钥、云厂商凭证、其它项目…     │
│                                                    │
│  网络（白名单）                                     │
│   · api.anthropic.com     （模型 / 系统）           │
│   · api.github.com        本项目始终允许  [ 撤销 ]  │
│   · api.npmjs.org         本项目始终允许  [ 撤销 ]  │
│                                                    │
│  工具 · 密钥 …（只读说明）                           │
└────────────────────────────────────────────────────┘
```

| 规则 | 说明 |
|---|---|
| **要**做在工作台里 | 边界条 → **权限一览**弹窗 → 网络行旁 **撤销**；侧栏「已记住」与最近活动「本项目始终允许」亦可行内撤销 |
| **不必**再做 | 工作台顶栏单独「撤销网站」按钮 |
| 禁止 | 「允许全部网络」快捷开关 |

文件 / 工具 / 密钥区保持说明性只读；仅网络「用户记住的允许/拒绝」可撤销。

**与设置「管理已记住的网站」不冲突**：

| | 工作台 · 权限一览 | 设置 · 网络安全 |
|---|---|---|
| 数据 | **同一存储**（按工作区路径 + 域名） | **同一存储** |
| 默认视图 | 优先当前会话工作区（可切「全部项目」） | 全机汇总（按路径区分项目） |
| 何时用 | 跑着 Agent、刚点错「始终允许」、就地改 | 不在会话里、要清多个项目的历史 |
| UI | 同一列表组件 / 同一 `listRememberedHosts` · `revokeHost` API | 同左 |

不是两套规则、也不会出现「这里撤了设置里还在」；任一侧撤销后另一侧刷新即消失。

### 5.6 工具（MCP）

让 Agent **能办事**（查文档、建 Issue…）。登记的是 **MCP 服务**，不是大模型。

```
│  工具                                      [ + 添加 ] │
│  MCP：远程 HTTP（浏览器 / Token）或宿主 stdio。         │
│  预置：☑ 本机时间  ☑ filesystem  ☑ Context7            │
│                        [ 添加所选 ]                     │
│  与「模型」不同：这里不负责 Claude/GPT。               │
│                                                        │
│  GitHub     浏览器登录 · ● 已连接      [ 编辑 ][ 删除 ]│
│  Notion     API Key · ● 已连接         [ 编辑 ][ 删除 ]│
│  本地 fs    stdio · /opt/.../npx · ●   [ 编辑 ][ 删除 ]│
```

| 操作 | 含义 |
|---|---|
| **预置勾选 → 添加所选** | `ListMcpPresets` / `AddMcpPreset`：本机时间、演示 filesystem、Context7（后者须 Token） |
| **编辑** | 打开与「添加」同构表单；可改名称/地址/认证方式；浏览器路径可再点「打开浏览器登录」，API Key 路径可贴新 Token（即原「重新登录 / 轮换密钥」） |
| **删除** | 二次确认后从列表与钥匙串移除 |

**不再单独放「重新登录」「轮换密钥」**：与模型页统一为编辑/删除，避免按认证方式分裂按钮。

列表仍标明**接入方式**（浏览器 / API Key / stdio），便于理解编辑表单会露出哪条路径。

#### 添加 / 编辑工具弹层

```
│  添加工具 / 编辑工具                                   │
│  名称  [ Notion          ]                             │
│                                                        │
│  接入方式                                              │
│  (•) 远程 · 浏览器登录 / SSO → [ 打开浏览器登录 ]      │
│  ( ) 远程 · API Key / Token  → 地址 + Key（提交清空）  │
│  ( ) 宿主 · 本地 stdio 进程  → 绝对路径命令 + 参数 + 环境变量 │
│                                                        │
│  说明：凭证/环境变量本机保存；沙箱只连 Gateway。        │
│                           [ 取消 ]  [ 保存并连接 ]     │
```

选「浏览器」时展示「打开浏览器登录」；选「API Key」时展示 HTTPS 地址 + Token；选「stdio」时展示绝对路径命令、参数与 `KEY=VALUE` 环境变量（进程在**宿主机**运行，经回环 HTTP 桥接）。公司 Wiki 等无 OAuth 时默认走 Token。编辑时预填名称与当前接入方式。

**自定义地址（Token 轨）**：可填任意 HTTPS MCP 端点（常见以 `/mcp` 结尾，不是模型 `/v1`）。保存成功后账号带探测到的工具列表；开会话用该列表白名单。若旧账号无工具列表导致创建失败，删除后重新「保存并连接」。会话 running 时仍可添加新工具账号（不自动挂到当前会话）。

**宿主 stdio**：只添加你信任的命令；应用重启后自动按已存命令重拉回环桥（端口可能变化）。若命令不可用则账号仍在列表，需在工具页重新探测。OAuth 轨提供 IdP 自助登记说明（DCR / 固定回调端口 / env client_id）。

**为何保留多轨：** MCP 生态里 Notion / GitHub / 公司 SSO 常只有 OAuth；内网 Wiki 常只有 Token；大量开源 MCP 仍是 stdio。V1 不做「读浏览器密码库」，也不在沙箱内直接拉起 stdio。

禁止：在工作台/向导里出现「在沙箱内填写 Key」的任何入口。

### 5.7 模型（V1 = 自由添加的 OpenAPI 配置）

让 Agent **能对话 / 编码**。形态对齐 VS Code：用户自己 **添加**「名称 + API 地址 + API Key」；**无浏览器登录**；**不强制预置下拉框**。

#### 为何去掉「预置下拉 + 未配置」

| 旧做法 | 问题 |
|---|---|
| 添加时下拉选 Anthropic/OpenAI… | 无法直接加 Minimax/公司网关等「其它模型」 |
| 列表里永远有 ○ 未配置 | 与「编辑 / 删除」重复：没配就不该占一行；有编辑删除就够 |

**新原则**：列表里出现 = 已经添加过；没有的模型用 **+ 添加** 新建；改用 **编辑**，去掉用 **删除**（二次确认）。

#### 5.7.1 列表

```
│  模型                                    [ + 添加 ] │
│  自行添加模型：名称、API 地址、API Key。                 │
│                                                          │
│  我的 DeepSeek     api.deepseek.com      [ 编辑 ] [ 删除 ] │
│  公司网关          llm.corp.local        [ 编辑 ] [ 删除 ] │
│  Minimax           …    ▲ 无效（401）     [ 编辑 ] [ 删除 ] │
```

| 元素 | 规则 |
|---|---|
| 顶栏 | **+ 添加**：打开添加弹窗，自由填写 |
| 行 | 仅已添加项；每行 **编辑**、**删除** |
| 主文案 | 用户起的**名称** + 地址主机名（不显示 Key） |
| 状态 | **默认不标「已配置」**（在列表里即已添加）。仅当出站失败时标 **▲ 无效** |
| **编辑** | 改名称 / 地址 / Key（Key 不回显，V1 编辑时必填重贴） |
| **删除** | **二次确认**后从列表与钥匙串移除 |

#### 5.7.2a 删除二次确认

```
│  删除模型？                                            │
│  将删除「我的 DeepSeek」及其本机 API Key。               │

│                         [ 取消 ]  [ 确认删除 ]         │
```

- 若有 running 会话正在用该模型：额外警告须先切换模型或停止会话。

#### 5.7.3 状态还要不要？

| 状态 | 是否保留 | 原因 |
|---|---|---|
| ○ 未配置 | **不要** | 没添加就不在列表 |
| ● 已配置 | **不要**（默认） | 在列表 = 已添加，多余 |
| ▲ 无效 | **要** | Key/地址错了时提示编辑，避免开会话才失败 |

- 浏览器登录 / OAuth
- 预置「未配置」占位行 + 必选厂商下拉

- 在沙箱内打开本表单

#### 5.7.5 与其它页联动

### 5.8 设置

设置页只改**本机默认偏好**，不改正在跑的会话（除非文案标明「立即生效」）。
**无「关闭隔离 / 在本机直接跑 Agent」**；隔离能力以状态区为准，失败只能「重新检测」。

#### 5.8.1 页面结构

```
┌─ 设置 ─────────────────────────────────────────────┐
│  默认偏向安全。改完即保存，无需点「应用」。              │
│                                                      │
│  ▸ 隔离后端（P2：Seatbelt / Docker；改后须重启）       │
│  ▸ 容器引擎（仅 Docker：Colima / 本机 Docker）         │
│  ▸ Agent（检测与安装；未安装可「复制安装命令」）         │
│  ▸ 会话默认                                          │
│  ▸ 网络安全                                          │
│  ▸ 结束与清理                                        │
│  ▸ 外观与侧栏                                        │
│  ▸ 关于（运行模式 mock/live；隔离逐条检测）            │
└──────────────────────────────────────────────────────┘
```

保存策略：**改即存**（本地偏好）。成功无打断；失败 toast「未能保存，请重试」。
有 `running` 会话时：多数项仍可改，但旁注「对下次新会话生效」；仅「结束与清理」里与停止流程相关的项对**下一次停止**生效。

#### 5.8.1b 隔离后端与容器引擎（P2）

```

│  二选一：Seatbelt（P1 默认）或 Docker（P2）。          │
│  Colima / 本机 Docker 只是 Docker 后端的引擎。          │
│  后端 [ Seatbelt（P1 · 默认） ▾ ]                     │

│  （偏好 ≠ 生效）[ 重启应用使生效 ]                     │

```

| 配置项 | 规则 |
|---|---|
| 隔离后端 | `UIPrefs.isolationBackend`=`seatbelt`\|`docker`；**改后须重启**；`HARBOR_RUNTIME` 优先于偏好 |
| 一键重启 | `RestartApp`；有进行中会话先确认；标题栏在待重启时也可点「重启应用」 |
| 引擎 | 仅 Docker 后端展示；托管 Colima 可钉扎下载；本机 Docker 只检测连接、不下载托管组件 |
| 失败 | fail-closed；阻断页主按钮「改隔离 / 引擎设置」聚焦本区 |

#### 5.8.2 Agent（检测与安装）

管理**预置 Kit 的本机可用性**，不是自定义 Agent 登记表。

```
│  Agent                                               │
│  请先按官方方式安装 CLI，再在此检测。API Key 在「模型」。│
│                                      [ 重新检测 ]    │
│                                                      │
│  Claude Code   ● 可用     路径已找到                  │
│  Codex         ● 可用     路径已找到                  │
│  dsh           ○ 未安装   [ 安装说明 ]                │
│                                                      │
│  （无「添加自定义 Agent」入口）                        │
```

| 操作 | 行为 |
|---|---|
| 进入设置本区 | 可显示上次检测结果；不强制每次重扫（避免卡顿） |
| 重新检测 | 扫描预置列表；更新状态；toast「已更新检测结果」；新会话 Step 2 下次进入看到同一结果 |
| 安装说明 / 复制安装命令 | 未安装项旁提供可复制安装命令（Claude/Codex npm；dsh 用 `scripts/install-dsh.sh`） |


| 配置项 | 控件 | 默认 | 生效时机 | 交互说明 |
|---|---|---|---|---|
| 未授权网站策略 | 单选三档 | 每次询问 | **下一次**扩权决策起生效；当前已弹出的模态仍按打开时策略收尾 | 「本会话记住」：仅 `session_id` 作用域；停会话清空。「本项目记住」：写入工作区策略，可在管理页撤销 |
| 管理已记住的网站 | 按钮 → 子页/抽屉 | — | 即时 | 见下方列表字段；空态：「还没有记住的网站」 |

**已记住的网站 · 列表字段（须能区分项目）**

| 字段 | 规则 |
|---|---|
| 域名 | 如 `api.npmjs.org` |
| 决定 | 允许 / 拒绝 |
| 范围 | **本会话** / **本项目** |
| **项目（工作区）** | 范围=本项目时**必显示**工作区路径（如 `~/work/foo`）；可截断，hover 全文。从「设置」打开的是**全机汇总**，必须靠此字段区分多个项目。从「权限一览」打开时可默认筛当前工作区，仍显示路径以免歧义 |
| 会话 | 范围=本会话时显示 Agent + 工作区短名（或 session 焦点名）；停会话后该项消失 |
| 时间 | 记住时间 |
| 操作 | **撤销** |

分组可选：按工作区折叠（`~/work/foo` 下若干域名）。V1 平铺 + 路径字段即可。

扩权模态三按钮与本设置的关系：

- 策略=每次询问：每次都弹；「仅本次」不写长期表；「本项目始终允许」仍可写项目表（用户显式点了才写）。
- 策略=本会话记住：用户点「仅本次」或「始终允许」后，同会话同域名不再弹。
- 策略=本项目记住：与点「本项目始终允许」等价地可写入；「拒绝」也可选择「本项目记住拒绝」（模态文案随策略微调，V1 可先只记住「允许」）。

| 关闭询问后的默认动作 | 单选（仅当开关关时启用） | 总是保留 | 同上 | 开关为开时，该单选 **禁用（灰）**；关掉开关后才可选 |

### 5.9 扩权模态（系统打断）

```
┌─────────────────────────────────────────┐
│  会话「Claude Code · ~/work/foo」         │
│  请求访问新地址                          │
│                                         │
│  api.npmjs.org                          │
│                                         │
│  [ 拒绝 ]  [ 仅本次 ]  [ 本项目始终允许 ] │
└─────────────────────────────────────────┘
```

- 多会话并行时**必须**展示是哪一条会话（Agent + 工作区）。
- 无「全部网站都允许」。
- 「本项目始终允许」写入**该会话工作区**策略。
- 拒绝后该会话 Agent 看到失败；活动列表记一条。

**选错「本项目始终允许」怎么改（V1 必有）**

弹窗本身无「撤销上一刀」；事后从列表删掉该域名即可，下次访问会再问：

| 入口 | 路径 |
|---|---|
| 设置 | 网络安全 → **管理已记住的网站…** → 按**工作区路径**找到该项 → **撤销** |
| 工作台 | **权限一览** → 网络 → **管理** → 同一列表（可已筛当前项目）→ **撤销** |

- 列表**必须标记项目**：本项目项显示工作区路径，不能只写「本项目」。
- 撤销即时生效，与「管理已记住的网站」共用同一数据源。
- 「仅本次」未写入长期表，停会话或本趟结束后自然失效，无需撤销。
- 「本会话记住」的项：停会话清空；也可在列表里提前撤销（范围显示「本会话」+ 工作区）。
- 扩权模态脚注可写一句：「选错可在权限一览或设置里撤销始终允许。」

### 5.10 隔离不可用（阻断页）

全页替代内容区；侧栏被遮罩时以阻断卡上的按钮为准（无「仍要继续」）。

文案示例：「这台电脑当前无法建立隔离环境。Agent Harbor 不会在无隔离时启动 Agent。」+ **七项逐条检测列表**。

**恢复路径（必有）**：主按钮 **「改隔离 / 引擎设置」** → 设置页聚焦「隔离后端」；Docker 未就绪时提示可改「本机 Docker」或退回 **Seatbelt**，并重启。次按钮「重新检测」（动画与引导/设置相同；Docker 七项文案）。已装 Docker Desktop 且仍选托管 Colima 时，设置页可一键切到本机 Docker。
