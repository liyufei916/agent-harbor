## 1. 文档说明

### 1.1 目的

定义一款**桌面端、安全优先、最终用户可上手**的 Agent 沙箱产品：用户无需理解容器、网络策略或密钥注入细节，即可在隔离环境中运行 Claude Code、Codex、dsh 等主流 Agent，并安全使用 MCP。

本文回答产品目标、威胁模型、范围与排期。**架构逻辑**与**页面设计**已拆出专文，避免总纲过长：

- 架构：`ARCHITECTURE.md`
- 页面：`PAGE-DESIGN.md` + `../prototype/index.html`

### 1.2 读者

产品、安全、客户端/桌面研发、Agent 生态对接、测试。

### 1.3 术语

| 术语 | 说明 |
|---|---|
| Agent | 可在本机执行命令、读写文件、调用工具的 AI 编程助手（如 Claude Code、Codex、dsh） |
| 沙箱 | Agent 及其子进程运行的隔离运行时；默认与宿主机文件系统、网络、凭据隔离 |
| 宿主机 | 用户本机 OS；凭据、MCP 注册、策略均驻留于此 |
| 工作区 | 用户显式授权给沙箱读写的项目目录（或沙箱内克隆副本） |
| 凭据代理 | 宿主机上的 HTTP(S) 出站代理：用真实密钥改写请求头，沙箱内只见占位符 |
| MCP 网关 | 宿主机统一代理所有 MCP 连接；沙箱只连网关，不持有 MCP 密钥 |
| Sentinel | 沙箱内配置里的占位 token/header 值，本身无权限；由代理替换为真实凭据 |
| Agent Kit | 针对某一 Agent 的预置镜像/启动脚本/配置模板，保证开箱可用 |

## 2. 背景与问题

### 2.1 现状

主流 Coding Agent（Claude Code、Codex、Cursor Agent、dsh 等）默认在用户本机以接近本人权限运行：

- 可读 SSH key、云厂商凭证、浏览器 Cookie、密码管理器导出目录等
- 可出网；遇提示注入可外泄代码与密钥
- MCP 常以 stdio/本地进程方式挂载，**密钥写在 Agent 配置或环境变量里**，一旦 Agent 被控即失守
- 内置 sandbox（Bash 沙箱、workspace-write 等）多为「降摩擦审批」，**不罩住 MCP、不保证凭据不出边界**

用户被迫在「不好用」与「不安全」之间二选一：要么关 YOLO / 每步审批，要么全盘信任。

### 2.2 竞品缺口

| 产品 | 强项 | 相对本方案的缺口 |
|---|---|---|
| Docker Sandboxes | microVM + 凭据代理 + MCP Gateway，架构最接近 | 偏 CLI / Docker 生态，非消费级桌面体验 |
| Cosmonic Desktop | GUI 友好、能力可视化、密钥引用 | Agent 本身仍在宿主机；沙箱的是生成代码/Wasm workload |
| Claude / Codex 内置沙箱 | 低门槛 | 隔离面不足；MCP/凭据模型不完整 |
| ai-jail / agent-sandbox / bwrap | 轻量、开源 | 技术化配置；不解决 MCP 密钥外置 |

**市场空白**：同时满足「强隔离 + 主流 Agent 开箱 + MCP/凭据永不进沙箱 + 非技术化桌面体验」的产品尚未成型。

### 2.3 机会

把 Docker Sandboxes 已验证的安全模型（microVM / 凭据代理 / MCP 网关）做成**面向最终用户的桌面产品**：安装即用、图形化授权、密钥只进系统钥匙串、Agent 一键启动。

## 3. 目标与非目标

### 3.1 产品目标（按优先级）

1. **安全优先**：Agent 进程及其工具链默认无法读取宿主机密钥与无关文件；出网经策略与凭据代理。
2. **凭据零进入沙箱**：模型 API Key、GitHub Token、MCP API Key / Password / OAuth client secret 等，**明文与可复用密钥永不写入沙箱磁盘或沙箱内配置**。
3. **MCP 配置无感**：用户在宿主机侧「添加 MCP」并完成登录/粘贴密钥；沙箱内 Agent 只看到网关地址与 Sentinel，**无需在沙箱内填写任何敏感信息**。
4. **主流 Agent 开箱**：首期支持 Claude Code、Codex、dsh；启动路径为「选工作区 → 选 Agent → 开始」，无 Docker/镜像命令心智。Agent 为预置 Kit：**始终出现在列表**，进入新会话时自动检测可用与否，设置中可手动「重新检测」；V1 不做自定义 Agent 表单。
5. **最终用户友好**：不要求理解容器、命名空间、策略语言；授权用自然语言与开关（「可访问此项目」「可推 GitHub」「可连 Notion MCP」）。
6. **隔离分期交付**（见 §7.4 / §7.6）：**一期**工作区权限隔离 + 进程降权（可部署本机或云主机）；**二期**容器隔离（物理机上按会话/租户起容器，例如一容器一访问入口）。Gate / 策略 / 页面契约跨期不变。

### 3.2 非目标（本期不做）

- **不做 IDE**：工作台不是 VS Code 式「目录树 + 编辑器 + 终端」；无内嵌文件浏览器与代码编辑。改文件靠用户本机编辑器或 Agent 在挂载目录内改；Harbor 负责隔离运行、边界可见、扩权与凭证闸口。
- 不做多租户云托管沙箱（可后续接云端备份，但不替代本机产品）
- 不做「防一切逃逸」的形式化证明；以实用威胁模型 + 纵深防御为目标
- 不替代企业 IdP / 密钥管理系统；与系统钥匙串、1Password 等对接即可
- 不强制 Agent 厂商改协议；以 Kit + 网关适配现有 CLI/配置约定
- 不在 V1 覆盖全部冷门 Agent / 任意自定义 MCP 二进制的完美兼容

## 4. 用户与场景

### 4.1 角色

| 角色 | 诉求 |
|---|---|
| 个人开发者 | 开 YOLO，又怕误删/泄密；希望「装个 App 就能安心跑 Agent」 |
| 安全意识较强的工程师 | 要看清边界：哪些目录、哪些域名、哪些 MCP 被授权 |
| 轻度技术用户 / 产品同学 | 会装 Claude Code，不会配 Docker / bwrap；拒绝复杂 YAML |

### 4.2 核心场景

1. **安心跑 Agent**：打开 App → 选工作区 / Agent / 模型（地址+Key）→ 开始。模型凭证在本机钥匙串，沙箱无明文。
2. **加工具**：在「工具」用 OAuth 或 API Key 配 MCP；与模型分开。凭证均在本机。
3. **看懂边界**：会话前/中可打开「权限一览」：工作区路径、允许域名、已挂 MCP、禁止路径（`.ssh`、`.aws`、钥匙串等）。
4. **审计与一键销毁**：查看本次会话访问过的域名与 MCP 调用摘要；结束会话可销毁沙箱磁盘，密钥从未在其中。

## 5. 威胁模型

### 5.1 假设对手

- Agent 被提示注入控制，执行任意 shell / 读写 / 出网
- 恶意或被投毒的 MCP 工具返回诱导内容，驱动 Agent 滥用权限
- 供应链：Agent 插件、skills、依赖安装脚本在沙箱内作恶

### 5.2 必须挡住

| 风险 | 控制 |
|---|---|
| 读取 `~/.ssh`、云凭证、浏览器资料、其它项目密钥 | 文件系统默认拒绝；仅挂载授权工作区（及只读 Agent 运行时） |
| 沙箱内配置文件被 `cat` 出 API Key | 凭据代理 + Sentinel；真实密钥只在宿主机进程内存/钥匙串 |
| MCP 配置里的 Bearer Token 被泄露 | MCP 网关在宿主机持证；沙箱只连 `mcp-gateway.local` |
| 任意出网外泄源码 | 默认域名/目的地白名单；超范围需用户批准 |
| 通过 Docker socket 逃到宿主机 | 不挂载宿主机 Docker socket；需要时用沙箱内独立引擎或禁止 |
| 执行 `reboot` / `shutdown` / 改系统服务等宿主机破坏 | **不能只靠「工作区路径」**；见 §7.6：非 root + 丢弃危险 capability +（一期）轻量封装 /（二期）容器 PID·mount 命名空间 |

### 5.3 明确不保证 / 残留风险

- **工作区本身可被改写或外泄**：授权目录对 Agent 可读可写；敏感仓需用户自担或选「克隆副本」模式
- **模型侧数据**：发往模型提供商的 prompt/文件内容不受本沙箱保密（另靠厂商协议与用户选择）
- **Hypervisor / OS 0-day**：依赖所选隔离后端的安全更新
- **用户主动扩大授权**：批准「全网」或挂载整个 `$HOME` 会削弱模型——UI 必须强警告
- **一期若仅做「目录 ACL、未降权」**：无法可靠阻止重启/装驱动等；产品**禁止**将此形态标成「已隔离」；达不到 §7.6 最低线则失败关闭

### 5.4 信任边界（一句话）

> 沙箱内一切不可信；宿主机上的凭据库、MCP 网关、策略引擎可信且为唯一持密钥组件。

## 6. 产品原则

1. **默认拒绝**：无文件系统、无网络、无环境密钥，直至用户授权。
2. **密钥只在宿主机**：任何「需要 Key」的能力，走代理/网关，不写进沙箱。
3. **授权可理解**：用「能做什么」表述，不用 iptables/seccomp 术语。
4. **Agent 可替换**：同一沙箱会话可换 Kit；MCP 与密钥注册与 Agent 解耦。
5. **可销毁**：会话结束可删运行时盘；不影响宿主机钥匙串中的密钥。
6. **失败关闭**：隔离后端不可用时拒绝启动，禁止静默降级到宿主机直跑。

## 7. 架构逻辑（摘要）

完整逻辑见 **`ARCHITECTURE.md`**。此处只保留评审用摘要。

### 7.1 两平面

| 平面 | 位置 | 持有真实密钥 |
|---|---|---|
| 控制面 | 宿主机：Orchestrator、Policy、Secrets、Harbor Gate（Proxy+MCP Gateway）、Runtime 管控 | 是 |
| 执行面 | 沙箱内：Agent Kit + Agent 进程 + 工作区 | **否**（仅 Sentinel） |

人话：**API Key 只存在你电脑上；Agent 在隔离环境里跑；它自己碰不到真密钥，出门联网时由本机代填。**

### 7.2 分层

`体验层 → 编排层 → 控制面服务 → 隔离层 → 执行面`。页面只调编排 API，不直操虚拟化。

### 7.3 三条主路径

1. **启动会话**：校验隔离 → 本机登录 → Policy 快照 → Runtime + Gate → Kit 注入 Sentinel → exec Agent  
2. **HTTPS 出站**：强制经 Proxy → 白名单 / 换头 / 扩权挂起  
3. **MCP**：沙箱只连 Gateway；上游密钥仅 Gate 使用  

### 7.4 隔离后端（与分期对齐）

| 期 | 隔离形态 | 对人说法 | 技术要点 |
|---|---|---|---|
| **一期** | 工作区权限隔离 + **进程降权**（轻量封装，非完整产品容器叙事） | 「只动这个项目；碰不到系统密钥；危险系统操作被拦住」 | 仅挂载授权工作区；敏感路径拒绝；出站经 Gate；**非 root**；丢弃 `CAP_SYS_BOOT` 等；可选 bwrap / sandbox-exec / 独立用户 |
| **二期** | 容器隔离（物理机上起容器） | 「每个会话/入口在独立容器里」 | 一容器一会话（或一租户一入口 URL/`index`）；独立 PID/mount/net；更强逃逸面 |

Runtime 可替换；**Harbor Gate / Policy / 页面契约跨期不变**。一期不得把「未降权的目录限制」写成已保护。原 L2/L3 对应二期强化容器 / microVM 预研，不挡一期先交付。

### 7.5 Agent Kit（首期）

Claude Code / Codex / dsh 为 P0。不改 Agent 源码为默认；无法挂钩系统代理则标记「不支持安全模式」并禁止默认启用。

### 7.6 一期专题：工作区隔离下如何限制 `reboot` 等 root 命令

**结论：按工作区挂目录只解决「能碰哪些文件」，解决不了「能不能重启机器」。一期必须同时做权限/能力隔离。**

| 手段 | 作用 | 一期要求 |
|---|---|---|
| Agent **永不**以 root / Administrators 跑 | 无密码则普通用户无法 `reboot`/`shutdown`/`systemctl` | **必做**：专用低权用户或当前用户降权子进程 |
| **禁止 sudo / 不进 docker 组 / 无密码免密 sudoers** | 堵住「提权后重启」 | **必做** |
| Linux：丢弃 capability（至少 `CAP_SYS_BOOT`、`CAP_SYS_ADMIN`、`CAP_SYS_RAWIO`、`CAP_SYS_MODULE`…）+ seccomp 黑名单（`reboot`/`reboot_syscall` 等） | root 二进制在无 cap 下也会失败 | 云主机 / Linux 本机 **必做** |
| macOS：Seatbelt / `sandbox-exec` 拒系统管理类操作；不授辅助功能乱授权 | 限制关机/改系统 | macOS 桌面 **必做对应 profile** |
| 不挂 `/var/run/docker.sock`、不暴露宿主机 D-Bus system bus、只读或不挂危险 `/sys` | 减少旁路关机与逃逸 | **必做** |
| 命令黑名单（拦截 `reboot` 字符串） | 可作审计提示 | **仅辅助**；可被脚本绕过，**不能当主防** |

**部署形态（讨论口径）**

- **一期**：控制面 + 降权执行面可装在**开发者本机**或**一台云主机**（多工作区 = 多会话策略，仍共享该机内核；靠用户/cap 隔离，不是多租户硬隔离）。
- **二期**：在**物理机（或大规格主机）上加容器**；例如「一个容器对应一个访问入口 / index」——网络与文件系统进容器命名空间，重启容器 ≠ 重启宿主机；宿主机重启需进宿主机特权面（Harbor 不把该面交给 Agent）。

**一期诚实边界（写进威胁残留）**：同机多租户、内核 0-day、用户把 Agent 加成 sudo——仍可能伤宿主机。二期容器把爆破半径收到「容器可毁、机器默认仍在」。

## 8. 页面设计（摘要）

完整线框与规则见 **`PAGE-DESIGN.md`**，可点 **`../prototype/index.html`**。

### 8.1 信息架构

HOME · 新会话 · 工作台 · **模型**（嘴）· **工具**（手）· 设置 · 扩权模态 · 隔离阻断页。

### 8.2 主路径

```
选工作区 → 选 Agent → 选模型 →（可选）工具 → 开始
```

会话中可切换当前模型；壳与工作区不变。HOME 可多会话；**同时 running ≤ 2**；**同工作区禁止双开**；同壳不同仓允许。

文案用语：「隔离运行 / 凭证留在本机」；「模型 / 工具」区分嘴与手。

### 8.3 硬性 UI 约束

- 厂商 Key **只在本机**（模型、工具）录入；工作台与向导无填密入口。  
- 扩权三按钮：拒绝 / 仅本次 / 本项目始终允许；**无「允许全部网络」**；多会话时标明是哪条会话。  
- 隔离不可用：失败关闭，无「仍要继续」。  
- **模型 V1**：自由添加（名称 + 地址 + Key），添加页无厂商预置下拉、无「未配置」行；仅 ▲ 无效有意义；无浏览器登录。**新会话 / 工作台选模型**用下拉，选项 = 已添加账号。  
- **工具 V1**：保留浏览器 OAuth/SSO + API Key 双轨。  
- 两页均不回显完整 Key；同工作区第二会话不得进入 running。

## 10. MVP 范围

### 11.1 必须有（一期 P1 / V1）

- Desktop App 或等价控制面（基础 GUI）
- **P1 Runtime**：工作区授权 + 敏感路径屏蔽 + **进程降权**（§7.6）；失败关闭
- Credential Proxy（至少覆盖 Anthropic / OpenAI / GitHub）
- MCP Gateway + 宿主机密钥存储
- Agent Kit：Claude Code（P0），Codex / dsh 跟进
- 权限一览（含撤销记住网站）+ 会话销毁
- 审计：域名命中、MCP 工具调用计数（无参数密钥）

### 11.2 明确延后（二期 P2 / V1.x）

- **容器 Runtime**（一会话或一入口一容器）；物理机部署
- Windows 对等体验；企业 MDM
- 动态 MCP 发现与组织级策略
- 沙箱内独立 Docker Engine；1Password / 企业 KMS
- 云端会话备份与跨设备同步；microVM 作为默认

### 11.3 成功指标（产品）

| 指标 | 目标（建议） |
|---|---|
| 新用户首次跑通 Agent | ≤ 5 分钟，无命令行文档 |
| 沙箱内检索常见密钥路径 | 不可读（自动化红队用例全过） |
| 主流 MCP 添加 | 用户零次在沙箱内粘贴 Key |
| 与「宿主机直跑」对比误触面 | 默认不可访问 `$HOME` 敏感树 |

## 11. 安全验收用例（节选）

1. 沙箱内 `cat ~/.ssh/id_rsa` → 失败（不存在或拒绝）
2. 沙箱内 `printenv | grep -i key` → 无真实云厂商/模型密钥
3. 沙箱内读取 Agent MCP 配置 → 仅 Sentinel / 网关 URL
4. 未授权域名 `curl https://evil.example` → 被代理拒绝
5. 授权 Notion MCP 后，抓沙箱磁盘与内存配置 → 无 Notion token 明文
6. 隔离后端不可用 → App 拒绝「开始」，无宿主机直跑回落
7. 销毁会话后，原沙箱盘不可再挂载出旧文件中的敏感残留（若曾误授权写入，另册）

## 12. 与竞品的差异化（对外表述）

| 维度 | 本产品 | Docker Sandboxes | Cosmonic Desktop |
|---|---|---|---|
| 形态 | 消费级桌面 App | CLI + Docker 生态 | 消费级桌面，偏 Wasm workload |
| Agent 位置 | **整进程在沙箱内** | 同左 | Agent 在宿主机 |
| 凭据 | 代理 + 钥匙串，零进入 | 代理，偏工程配置 | 引用密钥，边界不同 |
| MCP | 网关，沙箱无感密钥 | 已有 Gateway，体验偏工程 | 可沙箱化 MCP，模型不同 |
| 配置心智 | 选文件夹 / 点开始 | `sbx` 命令与概念 | 能力授予 / Inspect |

**一句话定位**：把「Docker Sandboxes 级安全模型」做成「能给非 Docker 用户用的桌面产品」，并坚持 **MCP 与 API 密钥永不进入沙箱**。

## 15. 附录：设计约束清单（实现时不得违反）

1. 真实密钥不得出现在沙箱文件系统、沙箱环境变量、沙箱内 MCP/Agent 配置明文中。
2. 不得挂载宿主机 Docker socket 或等价宿主管控面到 Agent 沙箱。
3. 不得在隔离失败时静默降级为宿主机执行。
4. MCP 添加与密钥录入 UI 只存在于宿主机 App，不存在于沙箱内向导。
5. 用户扩大到「整个 Home」或「全部网络」必须二次确认并持久标记为高风险配置。

### 17.4 并行与依赖（怎么拆才不互相堵）

```
W0 骨架 ─────────────────────────────────────────────

     ├─► W1 Runtime ──► W2 文件系统 ──────────────┐
     │         │                                  │
     ├─► W3 Proxy ───────────────────────────────┤──► 联调 / M1

     ├─► W4 Gateway ◄── W5 钥匙串 ───────────────┤
     │                                            │

              │
```

**可第一周就并行的三件事**（接口先写进 W0）：

- Kit 正式接入 ← Runtime 生命周期 API + Proxy/Gateway 地址约定已冻

### 17.6 拆成「多人项目」的仓库 / 职责边界

建议在 **https://github.com/liyufei916/agent-harbor** 单仓 monorepo 推进，按包分工，避免多仓协议漂移：

| 目录/包 | 负责人 | 对外接口（稳定契约） |
|---|---|---|
| `runtime/` | Runtime | `create/start/stop/destroy`、挂载、网络 namespace |

| `security/tests/` | 安全/QA | 红队用例，CI 阻断发布 |

人事约定：

- **跨包改契约必须走 Lead + 双 Owner 评审**（尤其 Sentinel 头格式、Gateway URL）

- 安全同学对 W1/W3/W4 有 **否决权**（违反 §15 可挡合并）
